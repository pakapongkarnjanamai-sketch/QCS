# QCS — Impeccable Design Context

## Design Context

### Users

**QCS has two distinct portals with different user types:**

**QCS.Web.Admin** — IT and system administrators who configure and monitor the procurement system. Their tasks are: managing users, roles, and departments; defining approval workflows; and monitoring procurement activity via the dashboard. Configuration tasks (setup/changes) happen occasionally; dashboard monitoring happens daily. Admins go directly to the relevant data grid — the dashboard is a secondary glance, not a primary landing zone.

**QCS.Web.User** — Office procurement staff and managers at a Thai organization. They process purchase requests, compare quotation documents, and move items through approval workflows (Purchaser → Verifier → Manager). Their day is spent scanning data grids, reviewing documents, and making approval decisions. Speed and accuracy matter — they need to find, compare, and act on information quickly without second-guessing what they're looking at.

### Brand Personality
**Friendly, clever, clean.**

- **Friendly**: Approachable and warm — not cold corporate. The interface should feel like a well-organized colleague, not a government form. Thai-language labels and copy should feel natural, not stiff.
- **Clever**: Smart about how it organizes and surfaces information. Progressive disclosure over overwhelming dumps. The UI should anticipate what the user needs next.
- **Clean**: Restrained, precise, uncluttered. Every element earns its place. White space is structural, not decorative.

**Emotional goal**: Confidence and trust. Users should feel the system is reliable, predictable, and in control. No surprises, no ambiguity in status or next actions.

### Aesthetic Direction

**Corporate-refined, data-dense.**

- **Light mode only.** The viewing context is daytime office work under fluorescent/natural light. Light surfaces reduce strain during extended use.
- **Data-dense.** Procurement teams scan large tables of requests, quotations, and approval statuses. Maximize information per viewport without sacrificing scanability. Tight but not cramped.
- **Corporate-refined.** This isn't consumer-facing — it doesn't need to "sell." It needs to feel like a premium internal tool that the company invested in thoughtfully. Think Bloomberg Terminal's confidence meets Notion's clarity.
- **DevExtreme Fluent Blue Light theme is fixed.** All design decisions must work within and complement this constraint. The blue primary (`#0f6cbd`) anchors the palette.
- **Typography**: Segoe UI is the current font. Consider complementing with a refined secondary typeface for headings/titles that adds warmth without clashing with DevExtreme's type rendering.
- **No brand colors to honor or avoid.** The existing blue is established and can remain the foundation.

**Anti-references** (what this should NOT look like):
- Generic SaaS dashboards with huge hero metrics and sparkline decorations
- Overly playful interfaces with rounded cards and pastel gradients
- Dark-mode-first "developer tool" aesthetics
- Anything that prioritizes visual novelty over task efficiency

### Portal-specific Direction

**QCS.Web.Admin** — Same palette and component language as the User portal, but with a slightly more neutral and formal tone. Admin surfaces should feel authoritative and precise — this is a configuration and oversight tool, not a task-execution interface. Reduce warmth slightly: pull back on friendly micro-copy, lean toward terse and exact labels. The navigation hierarchy and grid density remain the same. The visual signal that "you are in Admin" should be unmistakable but understated (e.g., a subdued accent or a "Admin" badge in the header) — not a completely different design language.

**QCS.Web.User** — The warmer, more human-facing side of the same design system. Progressive disclosure, friendly Thai-language copy, and workflow-guiding structure take precedence.

### Design Principles

1. **Confidence through clarity** — Every element should feel deliberate and trustworthy. Clear hierarchy, consistent patterns, zero ambiguity in status or available actions.
2. **Data-first density** — Maximize useful information per viewport. Procurement teams compare, scan, and decide — the UI should support that rhythm, not slow it down with excessive whitespace or decoration.
3. **Friendly professionalism** — Warm enough to feel approachable (especially important for Thai-language UI), polished enough to feel corporate. Not sterile, not playful.
4. **Clean intelligence** — The interface should feel clever through thoughtful information architecture and progressive disclosure — not through flashy effects or ornamental complexity.
5. **Quiet confidence** — Trust comes from restraint. Subtle transitions, precise spacing, muted accents. The system should feel solid and predictable, never showy.
6. **Admin precision** — In the Admin portal specifically, lean terse over friendly. Labels are exact, actions are unambiguous, the dashboard is a quick-glance instrument rather than a primary work surface. Admins navigate directly to grids — don't over-invest in the dashboard's visual weight.

### Technical Constraints
- ASP.NET Core MVC with Razor views (server-rendered)
- DevExtreme components (Fluent Blue Light theme, fixed)
- Bootstrap 5 grid + jQuery
- SignalR for real-time updates
- CSS organized: `core/variables.css` → `layout/` → `components/` → `pages/` → `utilities/`
- Thai-language UI throughout
