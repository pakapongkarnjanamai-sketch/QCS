# QCS — Impeccable Design Context

## Design Context

### Users

**Primary product for this scope: QCS.React.Admin**

- Primary users: IT/System Admin.
- Secondary users: Procurement admin staff.
- Context: daytime office operations; users jump directly into data grids and detail flows.
- Core jobs to be done:
	- Configure and maintain users, roles, departments, vendors, and workflow routes.
	- Review requests/quotations quickly and move work through approval checkpoints.
	- Monitor status exceptions and resolve operational blockers with minimal clicks.

### Brand Personality

**Friendly, clever, clean.**

- Friendly: approachable and calm, but not playful.
- Clever: information-first structure with progressive disclosure.
- Clean: restrained visual language, no decorative noise.

Emotional target: confidence and trust through predictable, unambiguous interactions.

### Aesthetic Direction

**Corporate-refined, data-dense, English-first.**

- Light mode only.
- DevExtreme Fluent Blue Light remains the anchor.
- UI copy language for React Admin: English-first.
- Visual references:
	- https://github.com/ (clarity, density, disciplined hierarchy)
	- https://aistudio.google.com/apps (clean information framing)
- Explicit anti-direction:
	- Overuse of color or high-saturation accents.
	- Inconsistent button styles across pages.
	- Generic SaaS hero/metric-card patterns.
	- Decorative effects that do not improve task execution.

### Design Principles

1. Confidence through clarity.
2. Data-first density with scanable hierarchy.
3. Single visual language for actions (button consistency).
4. Restrained color usage with blue as anchor accent.
5. Quiet, efficient interactions over decorative motion.
6. Admin precision: terse labels, direct paths, predictable behavior.

### Technical Constraints

- React 19 + TypeScript (strict) + Vite 8.
- Tailwind CSS 4 with token-driven styling in src/index.css.
- DevExtreme React 24.2 (Fluent Blue Light CSS loaded globally).
- React Router with appConfig basename.
- API integration via QCS.API with Windows-auth-compatible local behavior.

### Accessibility & Motion Baseline

- Accessibility target: WCAG 2.1 AA baseline.
- Motion baseline: subtle and purposeful only; keep existing motion policy unless feature-specific override is requested.
